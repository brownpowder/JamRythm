# Jam-Rythm UI/UX デザイン指示書 (Design Brief)

## 1. アプリの概要とコンセプト
- **コンセプト**: 「ポケットに入る専属リズム隊。コード感覚を養う伴奏＆作曲ツール」
- **概要**: アプリが自動生成したドラムとベースのループ再生（リズム隊）に合わせて、ユーザー自身がギターやピアノを弾いて楽しむアプリです。
- **特徴**: 画面に「現在のコード」が表示され、ユーザーは提示された「コード候補」を選んで変更しながら曲の展開を作っていきます。

## 2. ターゲット層
- ギターやピアノを練習している人
- コード進行から作曲のインスピレーションを得たい人
- 楽器を使って一人でもセッション（ジャム）感覚を楽しみたい人

## 3. デザインの方向性 (Tone & Manner)
- **視認性最優先**: ユーザーは**端末を譜面台に置き、楽器を弾きながら画面を見ます**（目線から距離60cm〜80cmを想定）。そのため、コード名や「今どこを再生しているか」が極めて大きく、ハッキリ見えるレイアウトが絶対条件です。
- **没入感とシンプルさ**: 気が散るような派手すぎるUIよりも、演奏に集中できる落ち着いたトーン（ダークモードベース、または洗練されたミニマルデザイン）を希望します。

## 4. 必要な主要画面

### ① ホーム / 生成設定画面
- **目的**: 曲の土台を作る画面。
- **UI要素**: Key（調）、BPM（テンポ）、ジャンル/ムードの選択UI、「セッション開始（Play）」ボタン。

### ② メインエディタ（プレイビュー） ※アプリの心臓部
- **目的**: 再生しながらコードを選び、演奏する画面。
- **UI要素**:
  - **現在のコード / 次のコード**: 画面内で最も目立つ特大サイズのテキスト。
    - ※「土台として鳴っているベースの音（コード）」と、「ユーザーが弾くために選んだコード」の役割の違いが視覚的にわかるデザインが理想です。
  - **コード候補ボタン (3〜4つ)**: 「安定(基本)」「切ない」「おしゃれ」「緊張感」などの感情ラベルが付随した、ユーザーが弾くための提案コード。
  - **譜面 / ギターTAB譜エリア [Pro]**: 選択中のコードの構成音やフォームを視覚化するエリア。
  - **進行インジケーター**: 現在再生中の小節・拍がわかるタイムライン（カラオケのテロップのように直感的なもの）。
  - **基本設定値の直接変更コントロール**: 再生しながらでもすぐに変更できるよう、Key（調）やBPM（テンポ）をメイン画面上で直接変更できるUI。
  - **プレイヤーコントロール**: 再生/停止、ループ設定など。

### ③ [Pro機能] 1画面全体コード譜（俯瞰）ビュー
- **目的**: 16小節〜の曲全体を、紙の楽譜（リードシート）のように1画面で俯瞰する。
- **UI要素**: グリッド状のコード進行表。演奏中にスクロール不要で全体が見渡せるレイアウト。

### ④ [Pro機能] 譜面 / ギターTAB譜エリア
- **目的**: 現在のコードの具体的な構成音を視覚化する。
- **UI要素**: 「五線譜」と「ギターTAB譜」が表示されるエリア。（※中身の描画自体はシステム側で行うため、デザイナー様には「ここに譜面が入る枠（プレースホルダー）」と、その周辺UIをデザインしていただきたいです）。

## 5. デザイナー様へのお願い・特記事項
- 楽器演奏時の利用を考慮し、**横画面（Landscape）での利用、特にiPadなどのタブレットでの使用感**も非常に重要になります。メインビューは横画面でのレイアウト案もいただけると助かります。
- コード候補ボタンの「感情ラベル（安定、切ない 等）」は、色分けやアイコンなどで直感的に伝わると素晴らしいです。
